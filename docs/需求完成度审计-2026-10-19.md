## 一、🔴 P0 阻塞项

### 1. 图片合同（PNG/JPG）直接用不了 —— OCR 未就绪
- **现象**：上传 PNG 实测返回 `status=parsing_failed`，提示"当前环境未安装 OCR 组件（PaddleOCR）"。
- **证据**：`backend/app/parsers/image_parser.py` 里 PaddleOCR 为 try-import，`requirements.txt` 未包含它。
- **PRD 条款**：2. 范围定义 P0 —「合同上传（PDF、DOCX、PNG/JPG 扫描件）」「多模态解析（OCR + 结构化提取）」。
- **补齐要点（有坑）**：
  1. `paddlepaddle` 有 cp312 win_amd64 wheel（3.3.1），可装；
  2. 但 `paddleocr` 3.x **改了 API**：现有代码用的是 2.x 写法
     `PaddleOCR(use_angle_cls=True, lang="ch", show_log=False)` + `ocr.ocr(path, cls=True)`，
     3.x 移除了这些参数、入口改为 `predict()`，**装上 3.x 现有代码仍会报错**；
  3. 二选一：锁 `paddleocr==2.8.x`，或改写 `image_parser.py` 适配 3.x；
  4. 首次运行还要下载 OCR 模型（约 20–100MB），离线/代理环境需预置模型目录。

### 2. Docker 部署必挂一个容器
- **现象**：`docker-compose.yml` 第 107 行 `celery -A app.celery_tasks.app worker`，
  但 `backend/app/celery_tasks/` 只有一个 **0 字节的 `__init__.py`**，没有 `app` 对象、没有任务。
  该容器启动即报 `Attribute app not found`。
- **PRD 条款**：5.4 并发与排队、README「Docker Compose 部署」。
- **补齐要点**：要么补 `app/celery_tasks/app.py` + 审查任务（配合第 3 条），
  要么先把 worker 服务从 `docker-compose.yml` 移除，避免答辩现场 `up` 就红。
  **当前状态属于"文档承诺了、代码没跟上"。**

### 3. 审查仍是同步阻塞，不符合 PRD 的异步模型
- **现象**：`POST /api/reviews` 在请求内同步跑完检索 + LLM，HTTP 连接一直挂到出结果；
  超时才 120s 兜底（`REVIEW_TIMEOUT_SECONDS`）。真实大模型下一份合同 30–120s 很常见，页面会卡死。
- **PRD 条款**：5.4「审查任务在后台异步执行，用户可离开页面，完成后在历史列表看到结果」；
  2.2「审查超时 → 返回已解析的合同结构，告知稍后在历史中查看」。
- **现状差距**：超时是直接抛 504，**不保留部分结果**，与 PRD 的"带不完整标记的降级报告"不一致。
- **补齐要点**：Celery/BackgroundTasks + 状态轮询（`reviewing` 状态已有枚举，但从未被写入过）。

### 4. 分页总数算错（真实 bug）
- **现象**：`GET /api/contracts?page=1&size=2` 实测返回 `items=2, total=2`，
  而库里实际有 9 条合同。前端分页器会永远显示"共 2 条"。
- **证据**：`backend/app/routers/contracts.py` 中 `total=len(items)`，取的是当前页长度。
- **修法**：`contract_service` 加一个 `select(func.count())` 同条件计数。

## 二、🟠 与 PRD 明文规则不一致

### 5. 总体风险等级没按规则算
- **PRD 规则**（4.3 Processing Rules）：≥3 条高风险 → 总体高；1–2 条 → 中；0 条 → 低。
- **现状**：直接采用 LLM 返回的 `overall_risk`（`app/rag/review_chain.py`），模型说高就是高。
- **风险**：同一份合同两次审查可能给出不同总体等级，一致性没保障；答辩问"你的总体风险怎么定的"会被戳穿。
- **修法**：拿到 `risk_items` 后按 `is_positive=false && risk_level=high` 计数重算，覆盖 LLM 值。

### 6. 追问没有 30 秒超时
- **PRD**：4.4 Exceptions「追问超时 [Assumption 30 秒] → 返回部分回复或提示重试」。
- **现状**：`app/routers/chat.py` WebSocket 流式转发，无 `asyncio.wait_for`，模型卡住就一直等。

### 7. 知识库不支持 TXT
- **PRD**：4.5「上传格式：DOCX、PDF、TXT（纯文本）」。
- **现状**：`admin_service` 复用合同解析器的 `supported_extensions()`，只有 pdf/docx/png/jpg，`.txt` 直接被拒。

### 8. 知识库管理页缺搜索框 + 分类筛选
- **PRD**：4.5 Layout「顶部：上传主按钮 + 分类筛选下拉框 + 搜索框」。
- **现状**：`KnowledgeManage.vue` 只有"上传知识文档"按钮 + 表格，文档多了没法找。

### 9. 历史列表缺「有 N 条追问」
- **PRD**：4.4 Result「在历史列表中，该审查记录显示『有 N 条追问』」。
- **现状**：`Home.vue` 列表只显示文件名/状态/时间，没有会话条数。

### 10. 法律免责声明不是固定文案
- **PRD**：4.4「必须明确声明『本建议仅供参考，不构成法律意见』」。
- **现状**：`chat_service.py` 的 system prompt 里是"你不是律师，涉及重大决策时提醒用户咨询专业法律人士"——
  意思接近，但依赖模型自觉，**不保证每次出现**。建议在 AI 回复气泡下方固定渲染一行声明（前端做，最稳）。
