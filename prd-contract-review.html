1. 背景与目标

1.1 问题陈述

企业合同审查长期依赖法务人员逐条人工比对标准模板、历史判例和法规条文，存在以下痛点：

  • 效率低：一份 50 页合同的完整审查平均需要 2–4 小时，法务团队人均月处理量有限，业务高峰期大量合同积压。
  • 一致性差：不同法务对同类风险点的识别标准存在差异，且难以覆盖所有专业领域（如税务、劳动、知识产权）。
  • 经验复用难：企业积累的合同模板、已审合同、审查意见、行业法规分散在个人电脑或共享盘，新人难以快速取用。
  • 非结构化输入：扫描件、拍照合同、图片协议无法直接审查，需要额外 OCR 步骤。

1.2 产品决策

基于以上问题，产品侧做出如下决策：

  • 以 RAG（检索增强生成） 替代单一大模型，使审查结论可追溯、可对齐企业自有知识；
  • 支持 多模态输入（PDF / Word / 扫描图片），覆盖企业常见合同来源；
  • 提供 对话式追问，让用户对单个风险点深入展开（如「这个违约金条款对我司有什么不利？」）；
  • 提供 管理后台 让业务方自主上传和维护知识库，减少对 IT 的依赖。

1.3 预期可观察结果

  • 用户可在上传合同后 [TBD，Assumption: 5–30 秒] 内获得结构化审查报告；
  • 审查报告中的每一个风险项均可点击查看其触发依据（对应知识库条目或合同原文位置）；
  • 管理员可自行上传一份 Word 模板到知识库并在 [TBD，Assumption: 1 分钟内] 内生效；
  • 用户可就同一审查会话发起至少 10 轮追问而无需重新上传合同。

2. 范围定义

以下为本产品 MVP（最小可发布版本） 的范围边界。P0 构成最小完整旅程，P1 是紧随其后的增强，明确排除项避免协作分歧。

🟢 P0 — 必做

  • 用户登录（管理员 / 普通用户两级）
  • 合同上传（PDF、DOCX、PNG/JPG 扫描件）
  • 合同多模态解析（OCR + 结构化提取）
  • RAG 检索 + 结构化审查报告输出
  • 对话追问（基于当前会话上下文）
  • 管理员知识库上传、列表、删除

🟡 P1 — 紧随其后

  • 审查历史列表与重新查看
  • 风险项确认 / 忽略 / 标记待改
  • 知识库编辑（替换内容，而非仅删除再上传）
  • 合同审查结果导出为 Word / PDF
  • 知识库版本历史

⚪ 明确排除

  • 合同在线编辑与修订
  • 电子签署与数字印章
  • 多企业 / 多租户协作
  • 工作流审批（法务负责人确认）
  • 企微 / 钉钉 / 邮件通知
  • 英文合同审查 [TBD]
[Assumption, TBD] 所有审查能力默认面向中文合同。英文合同若需支持将作为独立增强项进入 roadmap。

2.1 P0 最小完整旅程

用户登录 → 上传合同 → 系统解析 → RAG 检索 → 生成审查报告 → 对话追问
管理员登录 → 上传知识文档 → 系统切块入库 → 知识库可用

2.2 核心失败的恢复路径

失败场景恢复路径
合同解析失败（图片质量不足 / 格式不支持）用户重新上传；系统提示可能原因（如「图片模糊，请重新拍照」）
审查超时返回已解析的合同结构，告知「审查尚未完成，请稍后在历史中查看」
知识库检索为空系统使用基础通用规则输出审查，不阻断流程，并提示「知识库暂无匹配，建议管理员补充相关知识」
对话会话意外断开用户重新进入该审查记录，会话历史完整保留，可继续追问

以下按模块展开。每个模块包含目的、触发、处理规则、结果、异常。所有规则均为产品行为定义，不涉及技术实现。

4.1 FR-01合同上传与多模态解析

Purpose

让用户能够将企业常见来源的合同（电子文档、扫描件、拍照图片）转化为系统可理解的结构化文本，作为后续审查的基础。

Trigger

  • 任何已登录 普通用户 在「新建审查」页面点击上传区域或拖拽文件。

Layout

  • 上传区域：占据主视觉区，显示「点击或拖拽上传合同」+ 支持格式提示。
  • 文件列表：显示本次上传的文件，包含文件名、格式、大小、上传进度条、解析状态。

Processing Rules

规则说明
支持格式PDF、DOCX、PNG、JPG。[Assumption, TBD] 最大单文件 50MB。
文件校验超出格式或大小限制 → 阻止上传并提示具体原因。
解析流程PDF/DOCX → 直接抽取文本 + 版式结构；PNG/JPG → OCR 识别文本后结构化。
解析结果按「标题 → 章节 → 条款 → 列表项」层级组织，原文可回溯。
批量上传允许一次上传 ≤ [TBD, Assumption: 5] 个文件，逐个独立解析。

Result and State Change

  • 解析成功 → 合同状态变为 待审查，并显示「预览」按钮。
  • 用户可点击预览查看解析后的结构化文本，确认无误后点击「开始审查」。

Exceptions

异常场景产品行为
图片模糊 / 手写 / 倾斜严重标记 解析失败，提示「图片识别失败，建议重新拍照或提供清晰扫描件」，允许用户重新上传。
PDF 加密阻止解析并提示「该 PDF 已加密，请提供解密版本」。
文件无有效合同文本标记 解析失败，提示「未能从文件中识别出有效合同文本」。
用户中途关闭页面已上传但未完成解析的文件保留 [TBD, Assumption: 24 小时]，重新打开后可继续。

4.2 FR-02RAG 知识库与检索

Purpose

将企业自有知识（合同模板、历史判例、法规条文、审查指引）转化为可被检索的条目，作为审查结论的依据。

Knowledge Base 结构 [Assumption, TBD]

知识分类示例
合同模板销售合同模板、采购合同模板、劳动合同模板
审查指引法务部《合同审查要点 v2.3》、《民法典合同编关键条款》
历史判例本企业过往诉讼判决、典型纠纷处理记录
法规条文与合同相关的最新法律法规、司法解释

Processing Rules（检索行为）

规则说明
触发时机用户点击「开始审查」后，系统根据解析出的合同内容自动生成查询。
检索范围默认检索全部已启用的知识库条目。[TBD] 是否支持按分类限定。
返回内容每一个风险判断均附带检索命中的知识条目（展示其来源文档和文本片段）。
检索为空不阻断审查，系统切换为通用规则库继续输出，并在报告顶部提示「部分风险项未命中企业知识库，建议管理员补充」。

共享规则 — 知识条目切块

  • 单条知识库条目目标长度：[TBD, Assumption: 500–1000 中文字]；
  • 切块应尽量保持条款/章节完整，不截断关键法律条文；
  • 切块完成后方可进入「已启用」状态并被检索。

4.3 FR-03合同审查与风险报告

Purpose

将解析后的合同文本与知识库进行比对，输出一份结构化、可追溯的风险审查报告。

Trigger

  • 用户在合同预览页点击「开始审查」；
  • 或在历史列表中对 审查失败 的合同点击「重新审查」。

Layout

审查报告页面分为三栏：
  • 左侧（合同原文导航）：章节树状结构，点击跳转到中间原文位置。
  • 中间（合同原文 + 高亮）：合同全文，命中风险的条款以红/黄/绿色背景标注风险等级。
  • 右侧（风险项列表）：按风险等级分组（高 / 中 / 低），点击某一风险项 → 中间原文自动定位 + 底部展开详细建议和依据。

Processing Rules

规则说明
总体风险等级由高风险项数量决定：≥3 条高风险 → 总体「高风险」；1–2 条 → 「中风险」；0 条 → 「低风险」。[Assumption, TBD]
风险类别条款缺失、金额异常、期限风险、主体资格、违约责任、知识产权、保密条款、不可抗力、争议解决。[TBD] 可由管理员扩展。
每条风险项输出风险等级、风险类别、合同原文片段、问题说明、修改建议、触发依据（知识条目来源文档 + 文本片段）。
正向发现对合同中与企业模板一致、保护本司利益的条款，以「✓」标记作为正向参考。

Result and State Change

  • 生成审查报告，合同状态变为 审查完成；
  • 审查报告永久关联该合同，用户可随时查看；
  • 系统自动创建一个空的对话会话，引导用户开始追问。

Exceptions

异常场景产品行为
审查超时 [TBD, Assumption: 120 秒]返回已完成的部分风险项，报告顶部标记「本次审查可能不完整，建议稍后重试」。
解析内容过少（<50 字）阻止进入审查环节，提示「合同解析内容过短，请检查文件是否为完整合同」。

4.4 FR-04对话追问系统

Purpose

让用户围绕某一份审查报告进行自然语言追问，获取单个风险点的深入解释、对比和建议，而无需重新上传合同。

Trigger

  • 用户在审查报告页点击右下角对话图标；
  • 或在历史列表中进入已有会话继续对话。

Layout

  • 对话面板位于审查报告页右侧（或移动端底部弹出）；
  • 消息列表以气泡形式呈现：用户消息靠右，系统回复靠左；
  • 输入框底部固定，支持「发送」按钮和 Enter 快捷键。
  • 系统回复中若引用了合同原文或知识库条目，以可点击卡片形式展示。

Processing Rules

规则说明
上下文范围每次追问时，系统同时参考：当前合同全文 + 当前审查报告全部风险项 + 本会话历史消息。
引用来源系统回复中涉及合同或知识库内容时，必须展示其来源（如「合同第 5.2 条」或「知识库：销售合同模板 v1.2」）。
建议边界当用户追问法律定性类问题（如「这个条款合法吗？」）时，系统明确声明「本建议仅供参考，不构成法律意见」。
会话保留会话永久保留，关联对应审查报告。

Result and State Change

  • 每条用户消息和系统回复均追加到当前会话；
  • 会话最后活跃时间更新；
  • 在历史列表中，该审查记录显示「有 N 条追问」。

Exceptions

异常场景产品行为
追问超时 [TBD, Assumption: 30 秒]返回部分回复或提示「回复超时，请重试」。
当前会话引用的合同已被删除不允许进入会话，提示「该合同已不存在，会话已失效」。
用户连续发送空消息忽略空消息，不追加到会话。

4.5 FR-05管理后台（知识库管理）

Purpose

让管理员无需依赖开发即可自主上传、管理和维护企业知识库，保障 RAG 检索质量。

Trigger

  • 管理员登录后，点击顶部导航「知识库」进入管理后台。

Layout

  • 顶部：「上传知识文档」主按钮 + 分类筛选下拉框 + 搜索框；
  • 主体：知识文档列表，卡片式展示（文档名、分类、上传者、上传时间、切块数、当前状态、操作）；
  • 操作列：查看详情、删除、（P1：编辑）。

Processing Rules

规则说明
上传格式DOCX、PDF、TXT（纯文本）。[TBD] 是否支持 Markdown。
分类必填上传时必须选择一个知识分类（见 FR-02）。
切块状态上传后文档进入「切块中」，完成后自动转为「已启用」。切块失败 → 「切块失败」，管理员可删除后重传。
删除行为删除文档时其下属所有知识条目同时从检索中移除。[Assumption, TBD] 删除不影响历史审查报告中已引用该条目的风险项展示（保证历史报告可追溯）。
默认启用切块完成后默认「已启用」，立即进入检索范围。[TBD] 是否需要管理员手动点击「启用」。

Result and State Change

  • 上传成功 → 列表中出现新文档，状态为「切块中」；
  • 切块完成 → 状态变为「已启用」，可被新的审查任务检索；
  • 删除 → 文档从列表移除，其条目不再参与后续检索。

Exceptions

异常场景产品行为
上传格式不支持阻止上传并提示具体支持格式。
切块超时 [TBD]标记「切块失败」，管理员可重试或删除。
非管理员访问普通用户点击「知识库」 → 重定向到审查首页并提示「无权限访问」。

  • 管理员账号登录 / 退出。

  • 当多个用户同时触发审查时，系统按提交顺序排队处理，并显示当前队列位置 [TBD]。
  • 审查任务在后台异步执行，用户可离开页面，完成后在历史列表看到结果。
